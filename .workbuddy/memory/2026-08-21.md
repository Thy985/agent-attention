## Code Review：agent-attention (v0.2)

应请求对 `agent-attention` 已实现的代码/功能做了带证据的严厉审查。核心发现（均已在本地复现）：

1. **P0 紧急声音路径是死代码** — `src/notification/win32.ts:61` 与 `src/jump.ts:40` 用 `spawn(process.execPath, ['powershell', ...])`，但 `process.execPath` 是 **Node 二进制**，于是 node 把 'powershell' 当成模块加载 → exit 1。已用 `node _proof.js` 复现（exit code 1, node 模块加载器报错）。后果：`permission_required`(P0) 的"更响提示音"与"点击跳回 Terminal"功能从未真正运行。
2. **所有优先级声音无区分** — win32.ts 对每个事件传入相同 `sound: soundEnabled`，node-notifier 在 Windows 上走 snoretoast `-s Bottle`（已核对 node_modules/node-notifier/notifiers/toaster.js + lib/utils.js）。P0 与 P2 声音完全相同，违反 PRD §5.2/§12。
3. **Dedup 分隔符碰撞** — `src/dedup/index.ts:13` 用 `sha1("agent:event:message")`；`agent="a",event="b:c",msg="d"` 与 `agent="a:b",event="c",msg="d"` 哈希相同 → 第二个被错误抑制。已复现。
4. **Agent 自动识别全部退化成 'agent'** — `registry.ts:detectAgentId()` 检查 env(`CLAUDE_CODE`/`CODEx`/`OPENAI_WORKERS`) 与 `process.execPath.includes('claude'/'codex')`；但 CLI 运行于 node.exe，execPath 永不匹配 → `autoDetectAndRegister()` 永远返回 'agent'。已复现。违反 v0.3 规格 §3 原则2（禁止自动发现），且多 Agent Center 无法区分来源。
5. **PRD §22 / 验证报告失真** — PRD 声称 TeamMind 集成"62 tests pass"，但 `src/teammind` 已被 `chore: remove dead teammind code` 删除；实际测试 **60 passed** 且团队 mind 模块不存在；`dist/teammind/*` 是陈旧构建产物（mtime 15:47 vs 我 16:10 重新 build 未再生）。`docs/v0.3-p0-verification-report.md` 用 `AGENT_NAME=codex`（代码只认 `AGENT_ID`）伪证"多 Agent 可写"，且"用户听到声音"对 P1 `failed` 不实（P0 声音路径已死）。
6. **测试本身在保护 bug** — `tests/cli-invariant.test.ts` 与 `tests/jump.test.ts` 用源码字符串断言 `spawn(process.execPath`/`spawnSync(process.execPath`（"回归守卫"），反而把 bug 锁死；修 bug 会破坏测试。`tests/config.test.ts` "malformed YAML" 用例并未真正写损坏文件。`tests/state.test.ts` 声称测并发但用 `Promise.resolve(recordEvent)`（同步），实为顺序执行。
7. **`atomicWrite` 固定 `.tmp` 文件名**（`AttentionState.ts:74`）— 多个并发 `agent-notify` 进程（产品核心场景）争用同一 tmp → 事件丢失/损坏。v0.3 规格 §12.1 声称存在的 `tests/center.test.ts` 实际不存在（Center 分组/连接状态逻辑零测试）。

## Code Review（续）：Tray / 隐藏图标 / Center / 入口专项

用户要求深挖托盘、隐藏图标、Center 管理与入口（启动/点击/卸载）的 bug，重点在入口。已全部实机复现/读字节确认：

### 入口级（灾难级）
1. **Center 窗口在所有真实 Windows 上永远打不开** — `src/center/CenterWindow.ps1:12-13` 用 `New-Object System.Threading.Mutex($false, "Global\agent-attention-center-" + [WindowsIdentity]::GetCurrent().Name)`。本地/域账号的 identity name 必含反斜杠（本机 `LAPTOP-U14FALDT\lenovo`），Mutex 名禁止 `\`，构造即抛 `MethodInvocationException: 未能找到路径…的一部分`。该 `New-Object` 在 try 块**之外**（catch 只包 `WaitOne`），异常未捕获 → 脚本在 line 13 直接崩溃，**窗口从不出现**。已用 PowerShell 实跑复现（带 `\` 必 FAIL；不带 `\` 对照组 OK）。本地账号 NTAccount 也是 `机器名\用户`，故≈100% 真实环境必崩。
2. **install/uninstall 文件名不匹配 → 自启钩子永远删不掉** — `install-daemon.ts:27` 写 `agent-attention.vbs`（STARTUP_NAME='agent-attention'+'.vbs'），但 `uninstall-daemon.ts:15,18` 删 `agent-attention.lnk`。两处不一致 → 卸载永远找不到、删不掉自启钩子，卸载后每次登录仍尝试拉起 daemon。
3. **uninstall 杀光全机 node.exe（灾难级）** — `uninstall-daemon.ts:30-48` `tasklist /FI "IMAGENAME eq node.exe"` 后逐个 `taskkill /PID /F`。不区分是否本项目 daemon，把机器上所有 Node 进程（VS Code、其他 daemon、开发服务器、electron 应用）一并强杀。注释自称"conservative"，实为最激进。
4. **install 裸 `node` + 无 PID/无单例** — `install-daemon.ts:46` VBScript 用 `WshShell.Run "node" ...`（非绝对路径）；非交互登录 PATH 无 node 时自启静默失败。且 `:52` `spawn(process.execPath,[distDaemon],{detached:true})` 不写 PID、不查重、不与 daemon-cli 单实例管理对齐 → 重复 `npm run bin:install` 会拉起多个 daemon。

### 隐藏图标 / Tray（严重）
5. **TrayIcon.ps1 缺消息循环 → 点击大概率不响应** — `Start-Tray`(:114-149) 注册 Click/DoubleClick/ContextMenuStrip 后仅用 `while($true){$reader.ReadLine()}` 阻塞。`[Windows.Forms.NotifyIcon]` 必须在 `[Application]::Run()` 消息泵线程上才派发鼠标事件；`ReadLine()` 阻塞但不泵消息 → 左键/双击/右键点击不触发（图标可见但不交互）。缺 `Application.Run` 是确定性代码缺陷（无头环境不可观感，但代码层面确属缺失）。
6. **左键/Open Center 每次弹可见 PowerShell 黑框** — `TrayIcon.ps1:68` 与 `:123` `Start-Process powershell ... -WindowStyle Normal`；点击隐藏图标或选 Open Center 都闪黑色控制台窗口。双击 `:130` `Start-Process node ... mark-all-read` 依赖 `node` 在 PATH，缺失静默失败。
7. **`exit` 命令不真正退出** — `Invoke-Exit`(:151) 调 `[Application]::Exit()`，但从未 `Application.Run`，无消息循环可退；进程实际靠 stdin 关闭才退出。独立 `TrayIcon.ps1 exit` 进程（不共享 stdin）不会终止已运行的 tray。
8. **图标固定常驻、无"0 未读自动收起"** — `Start-Tray` 始终 `Visible=$true`，未读为 0 仍显示绿色图标（小问题）。

### Center 管理（严重/中）
9. **中文 UI 乱码（读字节确认）** — `CenterWindow.ps1`/`TrayIcon.ps1` 无 BOM，且字节为合法 UTF-8 但含字面乱码：`鈼?Connected`(:57)、`鈼?Last seen Nm ago`(:58)、`鈼?Unknown`(:154)、事件分隔符 `路`(:210)、`鈥\ue6c7nd`(:242)、头注释 `鈥?Tray Icon`/`鈥?Center Window`(:1)。Python 字节确认无 BOM、UTF-8 可解码但含 `鈼`(E9 88 BC) 等错误字符；即便 UTF-8 读取也显示乱码，zh-CN Windows（缺 BOM）PowerShell 按 GBK 读会进一步损坏。这些是暴露给用户的真实乱码。
10. **MiniPanel 是死代码，测试零覆盖真实交互** — `MiniPanel.ps1:2` 注释称"Dot-sourced by TrayIcon.ps1"，但 `TrayIcon.ps1` 从未 dot-source 它；其 `Format-EventMenuText` 用 `agent/event` 字段，与真实 `StateEvent` 的 `agent_id/type` 不符。Pester(`tests/center.ps1.Tests.ps1`)只测 MiniPanel 纯函数 → 测死代码；TrayIcon.ps1 的点击/菜单/图标/消息循环**零行为测试**，且 Pester 不在 jest 里跑。
11. **Center 一次性快照、无实时刷新** — `CenterWindow.ps1` 打开时读一次 state.json/agents.json，无文件监视/轮询；daemon 推送的新事件不刷新已开窗口。
12. **`Mark all read` 依赖 `node` 在 PATH** — `CenterWindow.ps1:281` `Start-Process node -ArgumentList $cliPath,'mark-all-read'`，node 缺失静默失败；路径 `..\..\dist\daemon-cli.js` 依赖仓库布局（全局安装后失效，同前 #8 cwd 问题）。

### 结论
入口层：1 个"所有真实 Windows 必崩"（Center 永远打不开）+ 2 个"卸载灾难"（删不掉自启钩子、误杀全机 node）。Tray 交互因缺消息循环+弹黑框基本不可用。Center 中文全乱码。最高优先级：#1（互斥体名去掉 `\`，改用 `[WindowsIdentity]::GetCurrent().User.Value` 即 SID，或 `Name.Replace('\','_')` 并去掉 `Global\` 前缀或用 `Local\`）、#2/#3（统一文件名、按精确 PID 杀）、#5（`Application.Run` + 隐藏窗口启动 powershell）、#9（补 BOM + 修正乱码字符）。
