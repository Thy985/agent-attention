## 1. 目标

把 v0.1（`agent-notify → Toast + Sound`）扩展为 v0.2（`agent-notify → Toast + Sound + State JSON`，`daemon → Tray + Mini Panel`），使 Agent Attention Center 真正成为"系统角落小图标"。

**不在范围内**（明确 defer，与架构文档 §四 一致）：

- ❌ TeamMind RuntimeEvent 订阅（70+ 事件类型）
- ❌ Lead Agent / 子 Agent 完成判断
- ❌ Notification Action 按钮（Allow/Deny）
- ❌ MCP / ACP / Hook 集成（除 `agent-notify` CLI 外）
- ❌ Quiet Hours / Focus Awareness
- ❌ 多用户路由
- ❌ 自动激活 Terminal/IDE（点击 Tray 条目 = 仅显示/清除）

## 3. 架构（具体到接口）

```
                ┌─────────────────────────┐
                │  agent-notify <event>   │
                │       <message>         │
                └────────────┬────────────┘
                             │
                ┌────────────▼────────────┐
                │  dedup (30s, in-proc)   │  ← v0.1 保留
                └────────────┬────────────┘
                             │ allow
                ┌────────────▼────────────┐
                │  Toast + Sound          │  ← v0.1 保留
                └────────────┬────────────┘
                             │ ok
                ┌────────────▼────────────┐
                │  Write State JSON       │  ← v0.2 NEW
                │  (~/.agent-attention/   │
                │   state.json)           │
                └────────────┬────────────┘
                             │ atomic write
                             ▼
                    state.json on disk
                             │
              chokidar watch │
                             ▼
                ┌─────────────────────────┐
                │  daemon (long-running)  │
                │  • reload State         │
                │  • update Tray Icon     │
                │  • refresh Mini Panel    │
                └─────────────────────────┘
                             │
                             ▼
                ┌─────────────────────────┐
                │  Tray Icon + 右键菜单   │
                │  (PowerShell + WPF)     │
                └─────────────────────────┘
```

**关键不变式**：

1. **CLI 不依赖 daemon**。daemon 关闭时，Toast + Sound 仍可用（daemon 关闭 = 仅失去 Tray Icon 计数；不视为错误）。
2. **State JSON 是唯一真相**。daemon 无内部缓存"应有状态"；每次重载都从磁盘读。
3. **daemon 不写 State**。避免并发写入冲突。

## 5. State JSON Schema

**路径**：`~/.agent-attention/state.json`（与 `config.yaml` 同目录）

```json
{
  "version": 1,
  "updatedAt": 1724070000000,
  "unreadCount": 3,
  "events": [
    {
      "id": "evt-1724070000000-a1b2c3",
      "timestamp": 1724070000000,
      "event": "permission_required",
      "priority": "P0",
      "message": "Codex: execute git push origin main?",
      "agent": "codex"
    }
    // ... 最近 20 条（按 timestamp 降序）
  ]
}
```

**Schema 约束**：

- `version`: 整数（当前 = 1）
- `events[].id`: 字符串，`evt-<timestamp>-<6char_random>`
- `events[].timestamp`: epoch ms
- `events[].event`: 限定为 4 个 EventName
- `events[].priority`: P0 / P1 / P2（由 `EVENT_PRIORITY` 映射）
- `events[].message`: 用户传入的 message
- `events[].agent`: 从 `process.env.AGENT_NAME` 读（v0.1 不传；默认 `"agent"`）

**State 操作语义**：

| 操作 | 行为 |
|---|---|
| `readState()` | 读 JSON；不存在返回默认值 `{version:1, events:[], unreadCount:0}`；JSON 损坏返回默认 + stderr 警告 |
| `recordEvent(input)` | (1) 读旧 state；(2) prepend 新 event；(3) 截断到 last 20；(4) atomic write（写 `state.json.tmp` → `fs.renameSync` → `state.json`）；(5) 返回新 state |
| `clearUnread()` | 读 state → 写 `unreadCount: 0` → atomic write |
| `clearAll()` | 读 state → 写 `events: [], unreadCount: 0` → atomic write |

**原子写保证**：Windows `fs.renameSync` 在同卷上是原子的（NTFS 内核支持）。state.json 与 state.json.tmp 在同一目录（`~/.agent-attention/`），保证同卷。

## 6. CLI 集成流（修改 `src/index.ts`）

```
main()
  ├─ extractArgs()         // 不变
  ├─ validate event        // 不变
  ├─ loadConfig()          // 不变
  ├─ config.enabled check  // 不变
  ├─ event enabled check   // 不变
  ├─ shouldNotify()        // dedup，不变
  ├─ await notify(...)     // Toast + Sound，不变
  ├─ recordEvent({...})    // NEW: 写 State JSON
  │   ├─ 失败仅 console.error，不影响 exit code
  │   └─ 失败时 daemon 不会 reload（预期行为）
  └─ process.exit(0)
```

**为什么 best-effort 写 State**：v0.1 承诺"通知成功即 exit 0"。State 写失败不应让用户重发通知。这与 daemon 只读的设计一致。

**`recordEvent()` 入参形状**：

```typescript
{
  event: EventName,
  message: string,
  timestamp: number,         // Date.now()
  priority: 'P0' | 'P1' | 'P2',  // 由 EVENT_PRIORITY 映射
  agent: string,             // process.env.AGENT_NAME || 'agent'
}
```

## 7. Daemon 生命周期

### 7.1 启动

**入口**：`src/daemon.ts` 编译为 `dist/daemon.js`。

```bash
# 注册到 Windows 启动项（首次安装时）
npm run start:daemon
# 或手动启动（调试）
node dist/daemon.js
```

**启动序列**：

1. 读 `state.json`（不存在 = 空状态）
2. 渲染初始 Tray（无未读 = `●`）
3. `chokidar.watch(state.jsonPath)` 启动监听
4. 进入事件循环：`on('change')` → 重新读 `state.json` → 调 `TrayIcon.ps1 update`

### 7.2 文件监听

- 用 `chokidar`（已成熟，Windows 下用 `ReadDirectoryChangesW`）
- 监听 `state.json` 单文件（不监听目录）
- `awaitWriteFinish: { stabilityThreshold: 100 }` 防止读到半写文件
- debounce 100ms 内多次 change → 只 reload 一次

### 7.3 Tray 更新协议

daemon 不内嵌 WPF 逻辑。daemon 用 `child_process.spawn` 调 PowerShell：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File src/center/TrayIcon.ps1 update
```

**TrayIcon.ps1 的 update 子命令**：

- stdin 传新 state JSON（避免命令行长度限制）
- 用 `NotifyIcon.Icon` 切换 `●` / `🔴 N`
- 刷新右键菜单（再读 state.json 自己渲染菜单项）

**为什么不内嵌 WPF**：PowerShell 进程崩溃不影响 daemon；daemon 可用 Node 测试（WPF 单独集成测试）。

### 7.4 错误处理

| 场景 | daemon 行为 |
|---|---|
| `state.json` 损坏 | stderr 警告 + Tray 显示 `●`（不报错状态）|
| PowerShell 调用失败 | stderr 警告 + 1s 后重试（指数退避，最多 3 次）|
| chokidar 报 EPERM | stderr 警告 + 5s 后重连 |
| 配置文件 `~/.agent-attention/daemon.json` 不存在 | 用默认配置（auto-watch 启用）|

### 7.5 退出

- 监听 `SIGTERM` / `SIGINT`：清理 chokidar 监听 → 退出 0
- 不自动重启（Windows 启动项会处理）

### 7.6 调试模式

`AGENT_ATTENTION_DEBUG=1` 环境变量启用：

- 每个 reload 打印 state diff 到 stderr
- PowerShell 调用保留 stdout/stderr
- 不写日志文件

## 13. 风险与回滚

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| PowerShell WPF 在某些 Windows 10 版本崩溃 | 中 | Tray 不显示，但 Toast 仍能用 | 文档说明"daemon 关闭 = 失去 Tray"；后续 v0.3 再换方案 |
| `shell:startup` 注册失败（权限） | 低 | daemon 不自启 | 降级：提示用户手动启动；记录错误到 stderr |
| 30s dedup 跨进程失效 | **已知** | 同一事件 30s 内从两个进程发会重复 Toast | 已知限制（v0.1 设计）；写 README "limitation" |
| state.json 损坏（手动编辑） | 低 | daemon 显示 ⚠ | readState 始终返回默认值；CLI 写会覆盖 |
| chokidar 在 OneDrive / 网络盘失效 | 低 | daemon 看不到 change | 文档说明"state.json 必须放在本地 NTFS" |

**回滚方案**：每个 PR 可独立 revert。如需整体回滚到 v0.1：

```bash
git revert --no-commit <commit-1>..<commit-7>
# 或
git reset --hard <commit-before-1>
# daemon 启动项需手动删除
```

**回滚代价**：低。每个 PR 都是独立功能单元。

## 14. 已知限制（写进 README）

1. **30s dedup 仅单进程内生效**。同一事件从两个 `agent-notify` 进程先后发会触发两次 Toast。要修：将 dedup state 也写到 state.json（v0.3）。
2. **点击 Tray 菜单条目只显示 Toast，不激活 Terminal/IDE**。架构文档 §四 defer。
3. **仅 Windows**。macOS / Linux 用对应通知方案（v0.3+）。
4. **Daemon 不是必须的**。不启动 daemon 时一切 v0.1 行为不变。
