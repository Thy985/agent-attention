# Agent Attention v0.2 Acceptance Criteria

> 本文件是 v0.2 的正式验收标准。每个 AC 必须在最终报告中标注 PASS / FAIL / NOT VERIFIED，
> 不得以"单元测试通过"代替真实环境验证。

---

## A. 安装与注册

### AC-01：Skill 可安装
用户通过明确安装方式将 agent-attention Skill 加载到 Agent。
验收：Skill 文件存在 | 可被目标 Agent 加载 | 加载后 Agent 能发现通知能力

### AC-02：Agent 自动注册
首次加载 Skill 后 Agent 必须注册自身信息。
至少包含：`{ agent_id, name }`
验收：注册成功 | Agent Registry 中存在 | 重复注册不会产生重复 Agent

---

## B. CLI

### AC-03：保留 v0.1 CLI
以下命令必须继续工作：
```
agent-notify completed "任务完成"
agent-notify permission_required "需要授权"
agent-notify input_required "等待输入"
agent-notify failed "任务失败"
agent-notify --event completed --message "任务完成"
```
验收：四种事件 + flags 形式均无报错退出 | exit code = 0

### AC-04：CLI 是独立可用的
daemon 未运行时：
```
agent-notify completed "test"
```
验收：写 State 成功 | 尝试 Toast | 尝试 Sound | 正常退出（不崩溃、不 hang）

---

## C. Attention State

### AC-05：通知进入统一 State
每个成功接受的 Attention Event 必须写入 State。
至少包含字段：id / agent_id / agent_name / type / title / message / priority / timestamp / read
验收：State JSON 包含上述所有字段 | 字段值与事件内容一致

### AC-06：State 保留最近 20 条
超过 20 条后删除最旧记录。只保留经过 Dedup 后接受的事件。
验收：写入第 21 条后 events 数组长度 = 20 | 最旧一条已被移除

---

## D. Dedup

### AC-07：30 秒 Dedup
相同 agent + event type + message 在 30 秒内重复发送只接受第一次。
重复事件不得：重复 Toast / 重复 Sound / 重复写 State / 重复增加 unread。
验收：30s 内两次相同事件 | Toast 仅出现一次 | State 仅新增一条 | unreadCount +1 而非 +2

---

## E. Windows 通知

### AC-08：四种事件真实触发系统通知
completed / permission_required / input_required / failed 各真实触发一次 Windows Toast。
验收：四种事件均触发系统通知（非 mock）

### AC-09：通知 backend 失败不能拖垮 Agent
Toast backend 卡死/异常时 agent-notify 仍须在 timeout 内退出，State 不得丢失。
验收：模拟 Toast 失败 | CLI 正常退出 | State 成功写入

---

## F. Sound

### AC-10：Attention 事件有声音
四类事件至少真实验证一次用户离开 Agent 后能通过听觉感知。
验收：四类事件各触发一次 | 用户可听到声音

---

## G. Tray / Attention Center

### AC-11：Daemon 启动后出现 Tray
```
agent-attention daemon start
```
验收：Tray Icon 出现 | daemon 保持运行 | 无黑窗口

### AC-12：State 变化后 Tray 更新
CLI 产生 completed / permission_required 后 Tray 反映未读状态（如 🔴 N）。
验收：发送事件后 Tray 图标计数更新

### AC-13：点击 Tray 可以看到 Attention
至少能看到：Agent name / event type / message / timestamp / read/unread
验收：点击托盘图标或右键菜单可查看事件详情

### AC-14：Daemon 重启后状态恢复
有 N 条 unread → daemon stop → daemon start → N 条仍然存在。
验收：stop 后再 start | unreadCount 不变 | events 数组完整

---

## H. 真实 Agent E2E

### AC-15：至少一个真实 Agent 跑完整链路
```
真实 Claude Code → 真实 Skill → 真实 agent-notify → 真实 State
→ 真实 Windows Toast → 真实 Sound → 真实 Tray
```
验收：完整链路一次跑通 | 每一步均有证据（日志/截图/进程状态）

---

## I. 真实用户场景

### AC-16：后台工作场景
```
Agent 执行耗时任务
  → 用户切到其他程序
  → Agent 完成/需要输入
  → 用户收到声音 + Toast
  → 用户打开 Attention Center
  → 看到正确 Agent 和事件
```
验收：用户感知链完整 | 无幻觉通知 | Agent 名称正确

---

## J. Agent 自执行能力（新增）

### AC-17：Agent Self-Execution
Agent 必须能够在无人工辅助的情况下完成所有其工具和权限允许的任务：
安装 / 配置 / 测试 / 启动 / 停止 / 重启 / CLI 验证 / daemon 验证。

失败标准：Agent 在未尝试自动执行的情况下，以"需要用户参与"为理由停止工作，
则该任务不视为完成。

验收：所有 daemon 生命周期操作均可通过 CLI 完成（无需手动终端操作）

---

## K. 工程契约（新增）

### AC-18：Self-Execution Before User Request
Agent 在请求用户介入之前，必须先经过 Self-Execution Check：
1. 识别具体阻塞操作
2. 检查可用工具能否执行
3. 尝试自动执行
4. 记录失败证据
5. 确认不是普通环境问题
6. 仍无法完成才请求用户

验收：Agent 报告任何 USER_REQUIRED 时附带阻塞原因和已尝试路径

### AC-19：User Escalation Gate
Agent 报告 USER_REQUIRED 前必须满足：
□ 已检查可用工具 | □ 已尝试自动执行 | □ 已检查权限
□ 已检查替代路径 | □ 已记录失败原因 | □ 已确认不是普通环境问题

验收：所有 USER_REQUIRED 报告均包含以上检查项
