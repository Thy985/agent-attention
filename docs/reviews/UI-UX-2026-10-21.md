# agent-attention：当前 UI/UX 源码审查与第六轮局部修复

日期：2026-10-21。审查基线：前五轮完整 tree `efe77dc3aff1ec2ed8448bc3c62553bd9667df2f`，不是最初仓库的旧问题清单。

## 结论

代码足以确认：此前桌面界面实现了托盘、窗口、通知列表和按钮，但信息解释、操作反馈、键盘入口及异常状态没有形成完整产品体验。把它称为“已有功能的界面样机，交互质量还没跟上”比“完全没做 UI”准确。

不能由代码推断作者不重视 UI 的态度，也不能在没有运行画面时给出整体视觉质量评分。本环境是 Linux，没有 Windows 桌面；本次没有声称看过真实 WPF 截图、完成真实窗口回跳或读屏验收。

## 现用路径与旧说法纠正

- `src/daemon.ts::runDaemon` 的桌面分支解析并要求 `AgentAttention.UI.exe`；Linux 明确走 headless。不把遗留 PowerShell 原型当现用 UI。
- 现用 Windows Host 是 `src/center/csharp/AgentAttention.UI/Program.cs`，WPF `CenterWindow` 配合 WinForms `TrayController`；不换技术栈。
- “UI 线程同步等待 CLI 进程”不能继续当作当前事实：第五轮 `CommandRunner` 已在 `Task.Run` 中等待进程。当前的问题是调用方不等待结果、不展示失败，而不是已经复现了主线程被 CLI 阻塞。
- `StateStore` 的本地文件读取和摘要生成仍在界面刷新路径同步执行；这是潜在延迟点，但没有实机卡顿测量，不能写成已经测到的冻结。
- 当前 Center 的整树重建确实仍在；Tray 菜单此前已经按 signature 避免不变状态重建，二者不能混为一谈。

## 可见改动与建议草案的区别

`ui-layout-proposal.png` 是用示例数据绘制的布局提案，图中已写明不是 Windows 运行截图、不是已实施的视觉升级。它用于讨论“请求优先、证据可读、下一步清楚”的方向。图中整体字体尺度、分区标题、按钮文案与留白是后续建议，不代表本次 WPF 实际渲染。

本轮真正实施的是上述局部交互修复；没有把整个窗口改造成图中的视觉设计，没有引入新前端框架，也没有构建 Wabi app。
