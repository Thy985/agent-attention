# Agent Attention Center v0.2 — 极小三层架构

**版本**: v0.2
**状态**: 架构设计（重写）
**核心边界**: "不解释 Agent 为什么完成，只把 Agent 想告诉用户的事情，可靠地交给用户"

---

## 一、产品边界（一句话）

> Agent Attention Center 是一个极小的人-Agent 注意力恢复协议 + 一个系统角落小图标。

它解决的是：**人离开 Agent 后，怎么被 Agent 叫回来。**

不解决：
- Agent orchestration
- 多 Agent event bus
- 任务依赖关系
- 谁触发、为什么触发

---

## 三、与 TeamMind 的关系

TeamMind 只是众多 Agent 之一。接入方式与 Claude Code 完全一样：

```bash
agent-notify completed "TeamMind 任务完成"
```

**没有 AttentionBridge，没有 RuntimeEvent 订阅，没有 Spring ApplicationListener。**

将来 TeamMind 真要接入时，它和 Claude Code / Codex / Qwen 一样，是 `agent-notify` 的一个用户。

```
Claude Code ────────┐
Codex ──────────────┤
Qwen Code ──────────┤
QwenPaw ────────────┤
TeamMind ───────────┤  ← 同等地位
其他 Agent ─────────┘
       ↓
   agent-notify CLI
       ↓
   Attention Engine
       ↓
   Attention Center
```

## 四、为什么不在 v0.2 范围

显式 deferred（不在 v0.2 实现）：

- ❌ TeamMind RuntimeEvent 订阅（70+ 事件类型）
- ❌ 任务依赖 / 下游阻塞判断
- ❌ Lead Agent 概念 / 子 Agent 完成判断
- ❌ MCP / ACP / Hook 集成（除 agent-notify CLI 之外的接入方式）
- ❌ Notification Action 按钮（Allow/Deny）
- ❌ Quiet Hours / Focus Awareness
- ❌ 多用户路由
- ❌ 自动激活 Terminal/IDE（点击 Tray 条目 = 仅显示/清除）

**这些都不在"注意力恢复"的核心路径上。**

## 七、与 v0.1 的关系

v0.1 完整保留：

```text
v0.1: Skill → agent-notify → Toast + Sound
```

v0.2 在 v0.1 基础上增加：

```text
v0.2: + State 持久化 + Tray Icon + Mini Panel
```

v0.1 CLI 路径不变。v0.2 的 daemon 在用户登录后自动启动，监听 `agent-notify` 调用并更新 State + Tray。
